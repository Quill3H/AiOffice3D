# Local Studio API v4

All paths except `/api/health` and sign-in require authenticated session or bearer token. Session mutation requires `X-CSRF-Token` from session response. JSON error: `{error,code}`. No client-supplied file paths or execution commands accepted. State carries monotonically increasing `revision` from persisted event IDs; clients ignore older snapshots.

`GET /api/tasks/:id/source` returns the original `{brief,kind,input,sha256}` to authorized admin/reader sessions; source contents are omitted from the bulk snapshot. QC verdicts are retained in each attempt as well as the current task. `GET /api/tasks/:id/history` returns the task-specific event history (up to1000, above the maximum generated by20 attempts) and all attempts/QC. The bulk activity feed contains only the latest300 global events; history remains persisted.

Local limits: 50 queued/running tasks, 500 stored tasks, 20 attempts per task, 100MiB reserved artifact output, JSON request 600KiB, source 500KiB (and 10,000 CSV rows/200 columns). Output budget is reserved before writing, including failed/interrupted attempts; previous outputs are never deleted to free space. Preserve a backup and use a new dedicated data directory when the workspace fills.

`POST /api/session {token}` → `{role,csrfToken}` and HttpOnly cookie. `GET /api/session` returns role/csrfToken; `DELETE` signs out. The local admin key is `.studio/access-token`, reader key `.studio/read-token` (both private, ignored).

`GET /api/state` → `{version,agents,tasks,artifacts,events,providers,connectors,skills,metrics,legacy}`. Tasks include `id,brief,kind,status,steps,attempts,qc,approval,revision,createdAt,updatedAt,error,version`; steps include `id,agentId,title,dependsOn,status,startedAt,finishedAt`; attempts include `id,number,status,startedAt,finishedAt,provider,model,mode,error`; artifacts include `id,taskId,attemptId,version,name,mime,size,sha256,createdAt` (no absolute paths). Events include `id,taskId,type,message,at,agentId`.

`POST /api/tasks {brief,kind,input,providerId?}` with header `Idempotency-Key` required → task (202). Kinds: `data_analysis` (input.csv), `html_audit` (input.html), `system_check` (empty input), `ai_draft` (input.context + optional agentId). `auto` resolves data/HTML/health keywords conservatively; otherwise AI draft. Input is JSON object; no filenames, paths or URLs fetched. All tasks require CEO approval. Missing required input creates BLOCKED task with reasons.

`POST /api/tasks/:id/retry {}` with new `Idempotency-Key` required → task. Only FAILED/INTERRUPTED/BLOCKED/NEEDS_REVISION may retry. Immutable request fingerprint prevents different requests reusing keys; repeating same retry key returns the current task without a new attempt. `POST .../cancel {}` cancels queued/running/blocked tasks. `POST .../review {action:'approve'|'revise',version,comment}` applies only to current AWAITING_APPROVAL version. Revision comment mandatory. Approval rechecks artifact integrity and QC before DONE.

`GET /api/artifacts/:id` downloads authenticated attachment. `GET /api/artifacts/:id?preview=1` sends text/plain for safe preview. `GET /api/events` authenticated SSE (`state` event on committed changes, keepalive); reconnect via GET state. `POST /api/providers/probe {}` probes only explicitly configured loopback endpoint. No paid provider call. `GET /api/legacy/:key` reads fixed read-only legacy documents; no path query. Legacy execution/bridge APIs return 410.

Agent IDs: manager, seo, content, video, design, development, qc, finance, advertising. Status vocabulary: QUEUED, RUNNING, BLOCKED, INTERRUPTED, FAILED, CANCELLED, NEEDS_REVISION, AWAITING_APPROVAL, DONE. No estimated progress percentage; render completed steps and event times.

## Gateway extension (09 November 2026)

The default provider route is `local-ai,muse,kimi`. `POST /api/providers/probe {providerId?}` probes the selected configured endpoint's model listing (default: first route member); it does **not** prove generation permission, billing or free quota. Unknown fields/provider IDs return 400. Existing local adapters whose probe returns void remain supported. `GET /api/state` lists every route member and `providerBudget`; task history additionally returns `providerCalls` with sanitized dispatch status/usage. No API key is returned or accepted in task/probe payloads.

Operator environment configuration (restart required):

| Provider | Model | Credential | Endpoint |
| --- | --- | --- | --- |
| local-ai | STUDIO_AI_MODEL | none | STUDIO_AI_BASE_URL, exact loopback |
| muse | STUDIO_MUSE_MODEL | META_MODEL_API_KEY | fixed https://api.meta.ai/v1 |
| kimi | STUDIO_KIMI_MODEL | MOONSHOT_API_KEY | STUDIO_KIMI_BASE_URL: https://api.moonshot.ai/v1 or https://api.moonshot.cn/v1 |

`STUDIO_PROVIDER_ORDER` is a comma-separated list of 1–3 unique IDs. No model is selected automatically. Credentials belong in private process configuration, never Git or chat. Use `providerId` on a task to prefer a configured route member. Only a fresh explicit probe (60s) enables dispatch. Response model must equal requested model, completion must finish with stop, output is bounded, redirects/tool calls are rejected.

**Zero-spend policy:** `STUDIO_REMOTE_CALL_LIMIT` defaults to 0 (integer 0–1000), is a lifetime workspace dispatch cap, and is not a monetary billing guarantee. Remote dispatch additionally requires per-provider operator-verified free entitlement for the exact configured model: `STUDIO_MUSE_FREE_QUOTA_EVIDENCE_URL` and `STUDIO_MUSE_FREE_QUOTA_UNTIL` (or KIMI equivalents). This is an operator attestation, not application verification of the provider account; public budget explicitly states `billingVerifiedByApplication:false`. Leave the cap at 0 unless the CEO has verified an actually free allowance and authorized use. A paid balance or web subscription is insufficient. No free allowance was verified in this implementation session; cloud generation remains disabled.

Each remote attempt is reserved in SQLite before dispatch. SUCCEEDED, FAILED and startup UNKNOWN reservations all consume the cap. A unique attempt/phase/provider tuple cannot dispatch again; a deliberate task retry creates a new attempt but still consumes the same workspace cap. Transport errors, 408,429,5xx and timeouts may advance to another already-probed provider once (maximum3 total providers), subject to that provider's own quota evidence and remaining cap. Caller cancellation, budget denial, malformed output/model mismatch and non-transient HTTP errors do not fall back. No background retry or auto-probe.

Schema2 is an additive migration for the provider ledger; newer versions fail before migration. Do not open schema2 data with an older unchecked runtime. Accepted AI context is <=100000 UTF-8 bytes; execution brief uses the shared 82000-byte bound to cover the existing 12000-character brief plus 8000-character CEO revision. Sign-in is bounded to10 attempts/minute/address including pending bodies and successful attempts.

Primary adapter contracts: [Meta Model API](https://dev.meta.ai/docs/overview), [Kimi API account/key distinctions](https://www.kimi.ai/help/kimi-api/api-troubleshooting). Muse consumer access does not itself demonstrate access to these API endpoints.

## Sourced-brief slice

`POST /api/tasks` accepts `kind:'sourced_brief'` (or auto with input.sources), optional configured providerId, and only `input:{sources:[{id,title,url,text}]}`. Supply1–5 sources with unique lowercase IDs (letter followed by up to39 letters/digits/underscore/hyphen), single-line title<=200 characters, HTTPS URL<=2048 characters without credentials, nonempty text<=20000 UTF-8 bytes each/60000 total; encoded source array<=70000 bytes. URLs are citation metadata, never fetched. The caller is responsible for obtaining and identifying source text; saved text is the evidence, not proof the URL actually contains it.

```json
{
  "kind": "sourced_brief",
  "brief": "Select source excerpts relevant to the CEO's question",
  "input": {
    "sources": [{
      "id": "s1",
      "title": "Synthetic fixture — replace with your verified source",
      "url": "https://example.org/fixture",
      "text": "This is synthetic test evidence, not external research."
    }]
  }
}
```

Manager returns strict JSON `{steps:[{id,agentId,title,dependsOn}]}`:1–3 sequential steps, roles content/seo/development, first dependsOn empty, each subsequent step depends on exactly its predecessor. Only these fields are accepted; commands/paths/approvals/unknown roles/cycles are rejected before specialist dispatch. Each specialist returns strict JSON `{claims:[{sourceId,quote}]}` with1–8 excerpts<=2000 bytes each and structured response<=20000 bytes. Context includes the assigned step and preceding structured handoff. Task deadline, cancel, bounded queue and20-attempt limit still apply; one attempt has at most4 logical generation calls (manager+3 specialists), each gateway call tries at most3 providers.

Validated plan/provenance and each handoff are saved transactionally in the attempt before the next dispatch, with PLAN_READY/HANDOFF_READY events and actual manager/specialist steps. Final immutable files are `plan.json`, `brief.json`, `report.md`; an interrupted attempt can retain its SQLite checkpoint without having final artifacts. No automatic replay of an interrupted attempt.

Independent worker QC does not import producer validators or report builders. It checks schemas, dependencies, source hashes/metadata, every literal excerpt and citation, stage provenance/content hashes and exact report reconstruction. Fabricated quote/citation => NEEDS_REVISION. PASS means these bounded technical/extractive checks passed; factuality, source authenticity, relevance, completeness, suitability and aesthetics remain UNVERIFIED. QC is an independent deterministic checker in this slice, not a second live model or live fact-checker.

Existing source/history/download/retry/review endpoints work unchanged; history includes persisted model plan and handoffs. Only explicit current-version CEO review can set DONE. This slice is accessible through API; the compose form still offers the original task kinds. `node scripts/demo-sourced-brief.cjs` runs a labelled offline protocol-double demonstration in a fresh temporary workspace, prints evidence locations and leaves the task awaiting approval; it never sends an API request or auto-approves.

Source manager/specialist calls use an internal bounded responseMode=json system instruction; ordinary ai_draft remains responseMode=text. This switch is server-owned, not a client API field or arbitrary system-prompt input. Transient error classification applies to both local and cloud adapters.

## Installed OpenCode worker pilot

Optional provider ID `opencode` executes the installed official CLI rather than calling Console Free endpoints directly. Enable only through trusted process configuration:

- `STUDIO_OPENCODE_BINARY`: absolute installed executable; on this Mac /Applications/OpenCode.app/Contents/Resources/opencode-cli.
- `STUDIO_OPENCODE_MODEL`: exact advertised Free ID, e.g. opencode/glm-5.3-flash-free. Free-suffixed model IDs and the explicitly listed Big Pickle are eligible; probe must advertise the exact selection.
- `STUDIO_PROVIDER_ORDER=opencode` (or a configured route with at most3 providers).
- Existing `STUDIO_REMOTE_CALL_LIMIT` defaults0 and still applies. `STUDIO_OPENCODE_FREE_QUOTA_EVIDENCE_URL` and `STUDIO_OPENCODE_FREE_QUOTA_UNTIL` use the same operator-attestation policy; these do not prove remaining account quota.

Probe checks CLI version >=2.2.6,<3 and the installed model catalog. CONNECTED records CLI_CATALOG_ONLY. Each dispatch runs a standalone process with an explicit Free model and a one-step text agent. The worker isolates config from inherited overrides and verifies config sources before dispatch. It preserves the existing account and data profile. It denies tools, plugins, MCP and search, with a 45-second generation deadline and bounded output. The executable is launched directly.

Success requires one stop completion, nonempty bounded text, no tool activity and CLI-reported cost0. Provenance records modelVerification=CLI_SELECTED_ONLY, CLI version, session ID, reported cost and relative trace ID. This is not an independently verified provider-returned model ID or billing audit. Source manager/handoffs retain this execution provenance.

Free-limit 429 persists RATE_LIMITED and retryAt across restart. A new task for the rate-limited provider shows the quota reason. A dispatch already in progress can fall back to another configured provider under the existing verified-free eligibility and call cap. The same OpenCode route remains in cooldown. Bounded stdout, stderr and per-call config are kept under the private opencode-worker data directory.

`node scripts/pilot-opencode.cjs --model opencode/<free-id>` runs an explicitly LIVE (not double) source workflow in a fresh temp data directory, max4 dispatch reservations. It leaves approval=null and writes pilot-evidence.json. It exits2 when generation was blocked/failed; that is not a successful model test. This script may make real Free-model requests only when explicitly invoked; it does not add credit/card or change the existing Desktop configuration.

On 09/11/2026 five distinct Free models returned provider.free-limit 429. A later GLM retry through the isolated worker returned the same error with a new reset deadline. The successful full flow uses process protocol fixtures. See docs/reviews/2026-11-09-opencode-pilot-results.md.
